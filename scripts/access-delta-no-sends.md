Scope: direct `User`, `Entitlement`, `OrganizationMembership` and `Organization` writes by `access:delta`, and their rollback. This is not a promise that a learner's later sign-in sends no mail. Sign-in and checkout keep their normal behavior.

## Read-only egghead-next audit

Paths below are relative to the separate `skillrecordings/egghead-next` checkout. It was inspected, not changed.

- `src/inngest/functions/identify-customer-io.ts:12-16,49-55` consumes `customer.io/identify`. The sender is an explicit tRPC mutation at `src/server/routers/customer-io.ts:14-34`, not a CourseBuilder row scan.
- `src/inngest/functions/send-specific-product-email.ts:11-17`, `send-workshop-quote-email.ts:12-18`, `send-feedback-email.ts:7-9`, `lifetime-purchase.ts:22-28` and `stripe-webhook-handlers.ts:13-19` require their named request, purchase or Stripe events. The delta emits none.
- `src/inngest/functions/index-lessons.ts:22-31,62-69` is the self-rescheduling job. It fetches published Rails lessons and submits indexing URLs. It does not scan the four CourseBuilder tables.
- Searches across `src` for the four physical table names, their entitlement/membership symbols, cron declarations and timer loops found content-author joins to `egghead_User`, but no job that scans these tables and sends signup, receipt or marketing mail. For example, `src/lib/get-course-builder-metadata.ts:184,260,992` joins users to content authors; it is not an insert watcher.

## Executable checks

- `scripts/access-delta-topup.test.ts` rejects Auth.js, Inngest, marketing and mail imports/calls in the direct SQL write path.
- `scripts/access-delta-fixture-proof.ts` leases only the disposable fixture credential in-process, checks DB triggers, seeds synthetic rows into the existing schema, applies, proves a raced edit refuses rollback, rolls back, compares every column of all four tables with the seed, then applies again.
- The existing MySQL suite and CLI canary test run on that same fixture credential. The CLI test covers dry-run rollback, target-confirmation refusal, a changed user selection, rollback, repeat-rollback refusal and reapply.

No live sends were tested by sending mail. No live or beta writes were made.
